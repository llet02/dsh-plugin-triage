# dsh-plugin-triage

插件冲突体检与治理（Plugin conflict triage for DeepSeek Harness）。

在「设置 → 插件」页新增一个 **「冲突体检」** 标签页，帮你回答三个问题：

1. **装了哪些、能不能用** —— 每个插件包与当前 DSH 版本的兼容性（`engines.dsh` 范围 vs 当前版本，含豁免状态）；
2. **谁和谁打架** —— 同类/重复注册冲突组，标红并显示数量；
3. **怎么办** —— 每个冲突成员可直接 **启用 / 禁用 / 删除 / 更新 / 替换**，按钮旁标注**后果**；
   顶部还有四个**一键**动作（更新 / 禁用冲突 / 禁用报错 / 翻译描述）。

外加一个**能力扫描**：每个已装包到底贡献了什么（工具 / 模型 / UI 视图 / Web 接口 / 命令 / 技能 / 子代理 / MCP / 后台任务 / 会话投影 / 本地存储 / 执行命令 / 插件目录），
每条标签都带 `file:line` 证据（悬停可见），顶部一行给出全机能力分布。

## 解决的问题

多装几个插件后常见的坑：

| 现象 | 本插件如何发现 |
| --- | --- |
| 两个插件包插入了**同一个加载入口 id**（重复注册），启动报错或行为错乱 | 冲突组「重复入口」，标红 + 成员计数 |
| 两个插件包装载了**同一个 npm 模块** | 冲突组「重复模块」 |
| 多个插件都声明依赖**同一个客户端模块**（如都注入 `@deepseek-ai/dsh-client-ui-settings`） | 不算冲突：单列为「共享客户端依赖」，由 DSH 复用同一模块实例 |
| 已安装但**已禁用**的插件与在用插件“看起来重复” | 不计入冲突：只有已启用的包和入口参与冲突判定 |
| 插件与当前 DSH 版本不兼容（`engines.dsh` 不含当前版本），下次启动可能被拒绝加载 | 「版本不兼容」问题 + 兼容表标 ✗ |
| 插件入口**加载失败 / 一直 pending** | 「加载问题」列表 + 诊断信息 |
| 需要**替换同类插件**：禁掉旧的、从官方目录（离线内置）或版本列表装新的 | 「官方目录」搜索区 + 「检查更新 / 更新到此版本」 |

治理动作全部走宿主 `pluginManager` 服务（与官方插件页同一条持久化通道），
所以启用/禁用/删除/更新都会正确写入 profile、在可能时即时生效（HMR），
需要重启时结果里会明确提示 `restart-required`。

## 安装

```bash
# 方式一：命令行（在本机 plugin 目录下）
dsh plugin add file:D:/dsh-plugin-src/dsh-plugin-triage

# 方式二：GUI
# 设置 → 插件 → 添加插件 → 粘贴上面的 file: 路径（或发布到 npm 后用包名）

# 方式三：从插件市场索引安装（发布后）
dsh plugin add dsh-plugin-triage
# 或：设置 → 插件 → 自定义插件索引 → 添加 market/index.json 的 URL
#     → 「发现」标签页里点安装
```

安装后刷新页面（或重启 DSH），打开 **设置 → 插件**，即可看到末尾的 **「冲突体检」** 标签页。
插件自己的开关在 **设置 → 插件 → dsh-plugin-triage**（或本标签页不显示时，检查
「插件 → 设置」卡片的 `enabled`）。

> 它会出现在 “Installed / Discover” 等标签之后；如果你配置了实验性插件市场，
> 它排在市场标签后面。

## 界面说明

- **顶部统计**：运行中入口数、已装包数、真冲突组数、问题数、第三方包（启用/总数）、共享客户端依赖数、受豁免版本数。
- **搜索框**：跨插件包名 / 描述 / 入口 id / 模块名 / 补丁声明 / 官方目录搜索；搜索结果置顶展示，
  区分「已安装」与「官方目录」，并带完整治理按钮；配合筛选 chips（全部 / 冲突 / 问题 / 兼容性 / 官方目录 / 第三方）。
- **一键禁用**：页面级「一键禁用冲突第三方包」「一键禁用全部第三方包」；冲突组内也有「禁用本组第三方包」。
  批量动作只影响第三方包，框架官方包不受影响；本插件自身始终保留，便于恢复。
- **冲突组卡片**（红底）：只统计**已启用**的包和入口（已禁用包不参与冲突）；类型徽标（重复入口 / 重复模块）+ 标题 + 启用成员计数；
  每个成员一行，带「禁用入口 / 启用入口」（入口级）、「禁用包 / 启用包 / 删除包 / 检查更新 / 设置豁免」（包级）。
- **共享客户端依赖**（蓝色信息区）：`dsh.client.inject` 的模块复用单独列出，默认折叠，不计入冲突。
- **第三方插件包**：用「第三方」筛选快速查看全部第三方包，按启用状态排序，可直接逐个或批量禁用/启用。
- **问题卡片**：加载失败 / pending / 版本不兼容 / 管理错误，附诊断与建议，可一键治理。
- **兼容表**：每个已装包一行 —— 版本、`engines.dsh` 声明、判定（✓ 兼容 / ✗ 不兼容 / ⚠ 已豁免 / ? 未声明）、
  治理按钮。
- **官方目录**：DSH 随安装包自带的官方插件目录（离线可用），可搜索、一键安装 ——
  这是「替换同类插件」的入口：先禁用/删除冲突旧包，再从这里装替代品。
- **一键治理条**：
  - **一键更新** —— 对非官方且已启用的包逐个检查远端版本，自动挑最高兼容版本更新（单次最多 20 个，逐个报告 updated / upToDate / failed）；
  - **一键禁用冲突插件** —— 按 `官方包 > 已启用 > 版本更高` 为每组保留一个成员，其余一键禁用；无法判定的组**不自动处理**，保持标红等人工决定（每组也有「按策略修复本组」）；
  - **一键禁用报错插件** —— 加载失败 / 包管理错误 / 版本不兼容一次清掉；已禁用的目标不再重复计入；
  - **一键翻译描述** —— 用当前 profile 已配置的模型把非中文描述译成中文，结果按 `name@version` 缓存在 `~/.dsh/cache/plugin-triage-translations.json`，版本变了才重译；工具栏 `描述：译文 / 原文` 随时切换。
- **能力标签**：每行插件显示能力标签（悬停看证据 file:line），顶部「插件能力分布」按已安装包统计 —— 用来快速回答“这套插件到底给了我哪些工具 / UI / 接口”。
- **后果提示**：每个治理按钮旁展示该动作的后果（可在设置里关闭）。

## 动作与后果（与宿主一致）

| 动作 | 后果 |
| --- | --- |
| 启用/禁用入口 | 立即生效；禁用会写 `disabled` 到 profile，重启后保持 |
| 启用/禁用包 | 包内所有行整体加载/卸载；文件保留，可随时切回 |
| 批量禁用第三方包 | 一次请求逐个禁用所选包；框架官方包与本插件自身不会被批量操作选中 |
| 删除包 | 卸载并移除依赖，功能消失，需重新安装 |
| 安装 | 立即下载纳入 profile；与当前版本不兼容的包会被管理器拒绝 |
| 更新 | 先校验兼容性；失败自动回滚原版本；部分更新需重启 |
| 设置豁免 | DSH 官方警告：可能崩溃或数据丢失，风险自担 |
| 一键更新 | 逐个检查并更新非官方包；失败自动回滚，部分需重启 |
| 一键禁用冲突 | 每组保留一个（官方优先）；无法判定的组不动 |
| 一键禁用报错 | 只针对报告判定的报错目标；已禁用的不重复处理 |
| 一键翻译描述 | 描述文本会发给你配置的模型提供方；译文缓存本机 |

> **注意**：版本不兼容的包被禁用后，需先在「兼容性」表格里为它**设置豁免**才能重新启用 —— 这是 DSH 的版本门控，不是本插件加的。

## 与同类插件的差异

联网调研时发现已有三个方向相近的社区插件，它们与本插件的定位不同：

- [dsh-compat-vet](https://github.com/liujianqiao701/dsh-compat-vet)：专注「下次启动会被拒载的插件」预警 + 一键隔离/卸载（带备份回滚）；
- [dsh-conflict-guardian](https://github.com/baisama-cloud/dsh-conflict-guardian)：启动时检测重复挂载/失败插件并自动停用、弹窗汇报；
- [dsh-conflict-doctor](https://github.com/ven314/dsh-conflict-doctor)：冲突诊断 + 修复建议文本。

本插件把「搜索 + 冲突分组（数量、标红、后果）+ 启用/禁用/删除/替换治理 + 版本兼容性（含豁免管理）」合并进官方插件页的一个标签页里，全部动作复用宿主 pluginManager 官方持久化通道。

## 工作原理

- **宿主半边**（`entry.js`）：启动时读取 `pluginManager.listPlugins() / listBundles() / listVersionExemptions()`，
  静态读取每个已装包的 `package.json`（`engines.dsh`、`dsh.client.inject`、关键词），
  计算冲突组与兼容判定，通过 `/api/dsh-plugin-triage/state`（GET）与 `/action`（POST，仅本机 loopback）服务；
  治理动作直接调用宿主 pluginManager。
  新增动作：`update-all`、`disable-conflicts`（可带 `id` / `dryRun`）、`disable-erroring`（`dryRun`）、
  `translate`、`translate-probe`（看 provider / 模型 / 选中的路由）、`capabilities`（全量能力+证据）。
  翻译走 `ctx.llm.stream({ provider, model, messages })`，只取 `text-delta` 分片拼文本。
- **浏览器半边**（`lib/client.js`）：向官方插件页的 `plugins.tab` 槽位注册「冲突体检」标签页，
  纯本地渲染，无任何外部依赖。

> 兼容性判定是**尽力而为**：`engines.dsh` 未声明的包标 `? 未声明`，最终拦截仍然由
> 插件管理器在安装/更新/启动时强制执行（其报错也会出现在「问题」区）。

## 已知限制

- 治理动作由宿主记录；`plugin-manager/changed` 事件驱动标签页自动刷新（另兜底 30 秒轮询）。
- 删除/替换涉及安装管理器操作时，按宿主 HMR 能力决定即时生效或重启（结果会提示）。
- 能力扫描是**静态关键字证据**（package.json / cordis.patch.yml / 入口与 lib 的代码行），不是运行时真实注册结果：
  它告诉你“这个包用了哪些贡献面”，不保证该行一定执行；每类最多留 3 条证据行。
- 一键翻译依赖宿主 `llm` 服务：没挂载 LLM 插件、或没有已配置的 provider 时，该按钮不可用（不影响其余功能）；
  翻译会消耗你配置的模型的 token，可在设置里写死 `translationProvider` / `translationModel`。
- 相同功能的判定基于入口/模块/挂载点/引擎声明等**结构性信号**，无法读懂插件内部逻辑；
  两个名称完全不同但功能相同的插件需要你自己在搜索后人工判断（工具已把相关线索都摆出来）。
